# Isolated Prune ownership

This explicit operator workflow executes one service-bound scheduled Prune request.
No daemon endpoint or network protocol is enabled by default.
The original executor, independent pins, authorities, protected chain and custody
journals retain their identities and obligations.

## Roles and placement

Create the service root under its intended operating-system owner before issuing
the service enrollment. `identity-create` generates separate service and transport
keys. The participant must be a different, non-root Linux user. The issuer,
consumer, controller, service, protection and witness roles remain distinct.

Create the original private stores under that service user from the outset.
Changing ownership of an existing store does not revoke open file descriptors
held by its old owner and is not a supported transfer procedure. There is no
automatic import, repair, key replacement or recreation of missing pin journals.

The owner checks canonical absolute paths, native ownership, permissions and
original key placement. Original roots must be private. Descendants may have
storage-engine read permissions within that private root, but cannot be writable
by other users, owned by another user, symbolic links or multiply linked files.
The service root and socket must be outside the original stores. A root-owned
sticky temporary directory is permitted as an ancestor; private descendants are
still required. Administrators remain trusted.

The private configuration includes the original base-state resources and their
commitment version. Encoding an empty `state.Memory` object cannot substitute for
that state. The owner retains the canonical configuration and a full public
inventory copy for later offline recovery. No private paths travel over the
socket.

## CLI sequence

`omd work-prune-service` uses `--action ACTION --mode review|run`. First review the
exact inputs, then pass the printed `--expected-review-id` to the same action in
run mode. Reviews do not load role keys or grant execution. Outputs are immutable;
retain the complete artifacts and their IDs outside the service root.

| Action | Inputs and result |
| --- | --- |
| `identity-create` | `--root`, `--out`; creates fresh keys and exports public identity |
| `identity-public` | `--root`, `--out`; exports the original public identity |
| `enrollment-prepare` | `--identity`, `--plan`, `--plan-id`, `--issuer`, `--guard`, `--out`; prepares enrollment before admission |
| `enrollment-sign` | `--input`, `--key`, `--out`; issuer signs the reviewed enrollment |
| `descriptor-prepare` | `--root`, `--input`, `--participant-uid`, `--out`; opens and reviews original admitted owners |
| `descriptor-sign` | `--input`, `--key`, `--out`; issuer approves the complete unsigned descriptor |
| `configure` | `--root`, `--input`, `--descriptor`, `--descriptor-id`, `--out`; repeats preflight and retains immutable configuration |
| `request-prepare` | `--descriptor`, `--descriptor-id`, `--nonce`, `--out`; prepares the single initial request |
| `request-sign` | `--input`, `--descriptor`, `--descriptor-id`, `--key`, `--out`; consumer signs the exact request |
| `serve` | `--root`, `--descriptor`, `--descriptor-id`, `--position`, `--socket`; serves as the isolated owner |
| `call` | `--descriptor`, `--descriptor-id`, `--request`, `--socket`, `--key`, `--challenge-out`, `--approval-out`, `--out`; participant approves a verified live candidate or reads the retained response |
| `inspect` | `--descriptor`, `--descriptor-id`, `--request`, `--response`, `--out`; verifies public retained evidence offline |
| `recover` | `--root`, `--descriptor`, `--descriptor-id`, `--position`, `--request`, `--out`; exports only a confirmed original outcome |
| `cleanup-socket` | `--socket`, `--socket-id`; removes the exact reviewed socket only after connection refusal confirms no listener |

Enrollment preparation takes the original plan without a fence policy. Signing
uses a raw 32-byte seed in a private file, not hexadecimal text. Use
`work-prune-fence-policy` with explicit `--service-enrollment` and
`--service-enrollment-id`, then rebuild the plan with that enrolled policy.
Complete the
existing scheduled admission and inventory workflow before preparing a service
descriptor. The descriptor binds the service root, exact original review and
scope, full fence policy and inventory bindings, configuration hash, service
transport identity and both operating-system users.

Export the private runtime with `work-archive-prune-scheduled --mode review` and
its existing original-root arguments, plus `--runtime-config-out`,
`--service-identity`, `--service-guard-url`, `--service-witness-network` and optional
`--service-witness-timeout`. The witness-network file must allow the public
transport key generated by the owner. No consumer or transport seed is passed
into the runtime export. The guard URL is explicitly configured; the enrolled
guard signature authenticates its choice.

Use `--position-out FILE` with `request-prepare` to export the initial cursor;
`call`, `remote-call`, `recover`, `settle`, `status`, `continue` and `inspect` can export the confirmed cursor using the same
flag. The initial position is sequence zero with a zero head. After an interrupted
call, `serve --request` may reconcile that externally retained exact request
against a later stored position. A different request or invented current cursor
cannot adopt an unknown attempt. Preserve the same request nonce and bytes;
creating a new request is not a retry.

Public codecs and offline signing are portable. The Unix transport requires
Linux kernel peer credentials. Unsupported systems refuse serving and calling
before reading role keys. The explicit authenticated remote caller is portable. This does not change the Windows, Linux or macOS binary
release matrix.

## One bounded exchange

The client verifies the issuer-approved descriptor and signed request before
dialing. Linux checks the server's kernel user ID; the server checks the
participant's kernel user ID and consumer signature. The owner opens the original
stores, compares the exact reviewed state, and synchronizes the signed intent
before execution.

The core retains a fresh service-signed candidate before handing a detached copy
to the exchange. The service signs a challenge binding that complete candidate
to the exact request and intent position. The participant verifies and retains
the challenge, signs only its original consumer claim, and retains the approval
before sending it. The
owner compares every claim field, verifies the signature and requires EOF on
the approval stream before collecting the original witness quorum.

The owner uses only its own private transport key for those witness calls. It
retains all original locks and the live session until the guarded atomic effect
and complete result have been saved. The outer signed response is synchronized
before it is sent. Neither review nor a historical response is a live permit.

The exchange has a two-minute ceiling, shortened by caller cancellation. Existing
witness and guard limits remain unchanged. At most eight connections are accepted
concurrently and the owner serializes actions. Shutdown closes connections,
cancels operations and drains handlers before the caller releases the owner.
Socket removal is a separate reviewed operation, never an automatic restart step.

## Interrupted work

An intent with no outer response stays held. A second call cannot mint another
session, discard a candidate or repeat deletion. Failure to receive a signature,
witness reply or guard result does not establish that the operation did not run.

Explicit recovery opens the original executor and independent pins using the
retained inventory. It accepts only a confirmed full signed result or the
existing full observed-effect settlement. A bare storage effect, unconfirmed
pin transition or missing session signature is insufficient. Finish required
original-journal continuation or settlement through its existing reviewed CLI,
with the service stopped, then repeat recovery. Each original replica still
requires its separate completion; no balance, budget or obligation is reset.

Once the outer response is retained, an exact retry returns the same bytes
without opening archives, witnesses or guards and without reading the consumer
seed. Partial files block automatic repair; event prefixes have the explicit
continuation path below. Copying
the whole host or rolling back the independent guard remains outside this local
placement guarantee.

The independent operator campaign, safe ownership transfer for existing
placements and replacement of an already enrolled service key remain
separate work. The two existing hosts share administration and cannot establish
operator independence.

## Reproducible checks

`make test-prune-service-isolation` runs the Linux process probe. Root is needed
only by the test orchestrator to start disposable service and participant users.
Original keys and stores are created by service UID 60000; participant UID 65534
receives only public artifacts and has no supplemental groups. The probe checks
actual deletion and storage floor, unchanged authority snapshots, private-file
access denial, wrong-user refusal, interrupted approval, shutdown drainage and
replay in a new owner process with original sources offline. The fixture's guard
and witnesses share its service account, so this is not an independence proof.

Both completed and held scenarios passed on each existing Linux host; the
[sanitized evidence](evidence/prune-isolated-service-20261102.json) records scope
and source hashes. The same
probe is required by CI with the race detector. Public codec fuzzing and local
CLI recovery checks are separate from this process test. Full process cuts at
outer publication and independently operated remote execution remain open.

## Explicit continuation of interrupted publication

Stop the owner before reviewing a partial event. Retain the complete signed
request, descriptor and last confirmed position outside the owner root. The
`continuation-review` action requires those artifacts, `--root` and `--out`. Its
public CLI review opens no owners. Running the reviewed action opens the original
owner and emits a `ReviewID` over its native placements, exact retained prefix,
target bytes and external request. This ID grants no execution.

Use `continue` with those same inputs and `--continuation-id ReviewID`, review
that action, then run it with its own `--expected-review-id`. An existing file
is appended in place, synchronized and never replaced or truncated. A changed
prefix or inode invalidates the review. Another interrupted append requires a
fresh review; preserve the longer prefix. `status` exports the exact original
snapshot. Both `status` and `continue` accept `--position-out`.

An incomplete intent can only be completed from the externally retained original
signed request. It becomes held and cannot launch a new session. A missing intent
is refused. An incomplete or absent response needs the confirmed full original
result or observed-effect settlement, with the executor and pins held through
publication. A complete valid outer response can be synchronized offline. A
conflict, missing signature or unconfirmed original transition remains held.
This workflow does not repair partial identity, key or configuration files.

## Authenticated relay

`relay-serve` runs on Linux as the descriptor's participant UID. Its required
flags are `--descriptor`, `--descriptor-id`, `--socket`, `--transport-key`,
`--transport-public-key`, `--client-transport-keys` and `--listen`. The last two
accept comma-separated explicit public keys and listen multiaddresses. The relay
has its own transport seed and no owner keys or access to original stores.

`remote-call` takes `--descriptor`, `--descriptor-id`, `--request`, `--address`,
`--transport-key`, `--transport-public-key`, `--relay-public-key`, `--key`,
`--challenge-out`, `--approval-out` and `--out`. The consumer key stays at the
caller. Public review precedes run for both actions. Transport keys must differ
from each other and all enrolled custody/service roles. `--timeout` is between
100ms and two minutes; it never extends existing guard or witness deadlines.

The explicit `/outcomemesh/prune-service/0` protocol authenticates QUIC peers,
pins the receiver identity and accepts only the configured caller keys. No
handler is registered by the ordinary node. The relay forwards signed artifacts
to its configured local socket, which still requires Linux peer credentials.
It verifies the full fresh challenge, exact approval and final input EOF before
forwarding approval. The owner independently repeats those checks. A disconnect
never authorizes a replacement request or automatic execution retry.

The caller verifies the complete service-signed response. A retained local output
can be inspected with both private seeds absent. If the output was lost, the
same request can retrieve the original confirmed response from a restarted
owner, without the consumer key, archives or witnesses. Held work stays held.
The shared administrators of the two available servers remain trusted.

`make test-prune-service-publication` kills the actual publisher at thirteen
intent, candidate, result and reply boundaries, including partial writes and
an interrupted continuation. These are process-death tests, not physical power
loss tests. `make test-prune-service-network` runs the owner, relay and caller
as separate Linux processes and UIDs, including cold restart, pre-approval
failure and loss of a response payload. For two hosts, run
`scripts/remote_acceptance/prune_service.py --config HOSTS.json --out REPORT.json`.
The configuration has `a`, `b`, `a_ip` and `b_ip`; each host specifies the absolute
`binary`, its `sha256`, and a host-pinned noninteractive `ssh` argument list.
Use the Linux integration test executable, not the production daemon. The
runner uses fresh disposable directories and test keys, then stops its children
and removes only those directories. It never changes firewall rules or existing
service roots. Guards and witnesses in this fixture share the owner account.

## Settlement after deletion without a retained final result

Stop serving before local maintenance. Keep the original owner, executor, pins,
authorities and protected chain. A retained intent with an actual storage effect
and no final result cannot be retried as a new execution.

1. Run `settlement-review` with `--root`, `--descriptor`, `--descriptor-id`,
   `--position`, `--request`, `--plan`, `--plan-id`, `--out` and optional
   `--proposal-out`. As with every action, first obtain its public CLI review,
   then use `--mode run --expected-review-id ID`. Run mode opens the originals
   but does not change accounting. The proposal is derived from their actual
   protected effect, not caller-provided diagnostics.
2. Use the existing `work-prune-settlement` workflow to sign the proposal in the
   consumer and controller roles, export the settlement witness scope, and collect
   the original policy's quorum. See [the full signing procedure](PRUNE_SETTLEMENT.md).
   A proposal, even with both role signatures, is not the full decision.
3. Repeat `settlement-review` with the full `--settlement` artifact and separately
   retained `--settlement-id`. Retain the returned original-owner `Review.ReviewID`.
4. Review `settle` with those same inputs, `--settlement-review-id` from step 3 and
   a fresh `--out` path. Run with its own public `--expected-review-id`. These two
   IDs have different purposes: one pins original state, the other the exact CLI
   invocation. Optional `--position-out` exports the confirmed service cursor.
5. Complete each original replica ticket through the scheduled completion CLI,
   using the full typed `PruneSettlement` evidence. Settlement itself does not
   release any ticket or reset previous spending.

`settle` publishes a response containing the settlement decision, never a newly
invented live-session result. An interrupted original transition requires its
existing exact journal continuation first. If the original settlement is already
confirmed but the outer response is absent or partial, use `continuation-review`
and `continue`. These work with archive sources and witness network offline and
preserve the original response prefix. A new original-state review is required
after state advances; network retries cannot refresh it implicitly.

The added CLI fields change local invocation review IDs. Regenerate public
reviews before applying commands with this version. Persistent artifact formats,
consensus rules and the relay protocol are unchanged.

`make test-prune-service-publication` also covers five settlement publication
boundaries. `make test-prune-service-network` also runs four failure scenarios
in both directions. To reproduce only these on two hosts, add `--failures` to
`scripts/remote_acceptance/prune_service.py --config HOSTS.json --out REPORT.json`.
The failure controls exist only in the integration test executable. The runner
preserves bounded test-helper logs on failure before removing disposable roots.

The process runner gives startup and ordinary replay 40 seconds. Its explicit
offline settlement phase has a separate 120-second bound because it includes
role signing, quorum collection, refusal checks and both replica completions
under the race detector. Child failure is still reported immediately. This does
not extend any production transport, guard or witness deadline.
