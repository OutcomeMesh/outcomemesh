# OutcomeMesh Core v0.3.0

Planned development release. This version has no release tag yet and does not
activate a public network. The list below records changes after v0.2.0.

## Unclaimed Prune closure

- A typed closure certificate binds the original scheduled request and witness
  policy to a controller-signed CloseUnclaimed quorum. It shares the same slot
  as execution claims and cannot be used to obtain an execution permit.
- `work-prune-fence-close` supports public review, explicit quorum collection
  and offline verification against a separately pinned plan. Exact output
  retries preserve the original certificate without private-key access or
  witness calls.
- Original witness histories survive partial votes, network outages and cold
  recovery. Competing claims and closure cannot both obtain a valid quorum
  under the existing independence assumption. Split votes remain held.
- `work-prune-scheduled-outcome --mode cancel-with-closure` now retains the full
  verified certificate through the original executor and independent pins.
  Its separate review binds the certificate ID and current owner positions.
  Interrupted publication resumes the exact retained record; a confirmed retry
  preserves its quorum bytes.
- Each original replica ticket can then complete through the existing reviewed,
  co-signed command workflow. Cancellation itself leaves every ticket open.
  Other obligations, spent operations and archive retention remain unchanged.

## Started Prune settlement

- A Started executor with a retained actual storage effect can settle without
  recreating its lost session signature. The original consumer and primary
  authority sign the exact claim/effect proposal; the original witness policy
  selects it in a separate request-wide decision scope.
- CLI preparation, signing, scope export, collection and verification precede
  reviewed original-owner application. The executor retains the full decision
  only after checking its actual protected storage effect. Deletion is never
  repeated and authority accounting is not changed by settlement.
- Export and separate replica completion bind the settlement artifact ID. A raw
  effect cannot replace it. Pending transitions resume their embedded original
  certificate; exact retry preserves the original quorum bytes. Missing effects
  and conflicting decisions remain held.

## Compatibility

The new artifact types do not change consensus, witness transport, existing
request encodings or authority entry formats. Cancellation v1 is explicit and
valid only for a matching fenced request; v0 bytes and IDs remain unchanged.
Older binaries cannot read v1 cancellation records and must not be used to
reopen an executor or pin journal after that transition. A bare closure
certificate does not complete a Prune ticket. The explicit observed-effect terminal record also requires upgraded readers.
Started tasks without a retained signed result or an applied observed-effect
settlement keep their obligations. The latter requires a separate witness
enrollment with original pins, never a reset of the execution history.

The compiler remains Go 1.27.3. Windows, Linux and macOS distributions retain the
platform coverage documented for v0.2.0.
